# Validation of Version 0.1.0

Local environment: macOS arm64, Python 3.12. NumPy/SciPy/scikit-learn provide
array operations, bounded optimization and CV; scikit-survival provides
survival metrics and an independent Cox regression reference.

The test suite checks:

- Logistic and tied-time Breslow Cox analytic gradients against finite differences.
- Unanchored ridge logistic coefficients against scikit-learn LogisticRegression.
- Event-normalized ridge Cox coefficients against scikit-survival CoxPH regression.
- Tau=0 and strong-anchor limiting behavior in a shared coordinate system.
- Original feature retention, including p>n and all-missing columns.
- Absence of screening and feature-budget parameters.
- Fold-local imputation/scaling using only permitted training patients.
- Source independence of the target-only baseline.
- Exhaustive layer-grid candidate count and search-size limits.
- Prediction shapes, original-scale coefficients, column-order checks and missing values.
- Monotone survival probabilities and explicit unsupported-metric handling.
- Binary horizon censoring rules, stability summaries, and priority membership.
- Reproducible synthetic datasets and coefficient-shift variance conventions.

The synthetic quick-start results are generated by `examples/quickstart.py`,
which uses all 36 predictors and prints metrics for three strategies. Full
CV records, coefficients and metric outputs are saved in `docs/example-output`.
The sample can favor a baseline; no outcome superiority is enforced in code.

These checks establish software consistency for tested settings, not a formal
proof of optimality, equivalence to every earlier R/Python script, reproduction
of saved manuscript panels, external validation, or clinical utility.
The GitHub Actions workflow is supplied for Linux Python 3.10/3.12, but remote
CI success is not claimed until those checks have actually run.

Run locally:

```bash
python -m pytest -q
python -m build
python -m twine check dist/*
```
